# Reflec Beat Simulator

A fan-made, clean-room rhythm game for Android tablets inspired by Konami's *Reflec Beat* (2010–2020). Notes glide toward a judgment line and are tapped the instant they cross it. The entire product depends on one feeling: **taps landing exactly on the beat.**

## Status

- **M0 — Calibration spike**: complete (editor scenes wired, device verification pending).
- **M1 — Playable baseline**: complete (tap notes, judgment, scoring, results).
- **M2 — Chart support**: complete (JSON chart loader, all note types, chart select UI, autoplay).
- **M3 — Authoring**: complete. Hand-authoring workflow with in-Unity preview (`Reflec Beat / Chart Preview`). See `docs/authoring.md`.
- **M4 — Single-player vs CPU rival**: complete. Optional `rival`/`gold` notes, deterministic CPU rival, Just Reflect gauge, HP bars, and duel outcome.

## Legal note

This project reimplements the gameplay concept only. It does **not** include any Konami copyrighted music, charts, artwork, fonts, or code. The bundled `PlaceholderBeat.wav` and `demo.rbchart.json` are original generated content. If you want to recreate official Reflec Beat patterns, you must obtain the rights or create original content.

## Setup instructions

### 1. Open the project

1. In Unity Hub, click **Open**.
2. Navigate to `D:\GitHub\reflec-beat-simulator` (Windows) or `/mnt/d/GitHub/reflec-beat-simulator` (Linux/WSL).
3. Open the project and let Unity import assets.

### 2. Generate scenes and prefabs

The scenes and prefabs are built by an editor tool so they stay in sync with the scripts.

1. In the Unity menu, choose **`Reflec Beat / Build M1 Scenes`**.
2. Wait for it to finish. This creates/updates:
   - `Assets/Scenes/CalibrationScene.unity`
   - `Assets/Scenes/ChartSelectScene.unity`
   - `Assets/Scenes/GameplayScene.unity`
   - Note prefabs in `Assets/Prefabs/`

### 3. Calibrate

1. Open `Assets/Scenes/CalibrationScene`.
2. Press **Play**.
3. Tap along with the beat. The calibration scene logs tap deltas and stores an input offset.
4. Press **Done** to go to the chart-select screen.

### 4. Select a chart and play

1. Open `Assets/Scenes/ChartSelectScene`.
2. Press **Play**.
3. The bundled demo chart should appear as a button.
   - If no charts appear, see **Troubleshooting** below.
4. Toggle **Autoplay** (the white square turns green) and select the demo chart.
5. The gameplay scene loads and autoplay should hit every note with **JUST**.

### 5. Build for Android

1. Go to **File > Build Settings**.
2. Switch platform to **Android**.
3. Confirm these scenes are in **Scenes In Build**:
   - `CalibrationScene`
   - `ChartSelectScene`
   - `GameplayScene`
4. In **Player Settings**:
   - Set **Default Orientation** to **Landscape Left**.
   - Set a package name, e.g. `com.yourname.reflecbeatsimulator`.
5. Connect an Android device with USB debugging enabled.
6. Click **Build And Run**.

## How chart loading works

At runtime charts are read from the device:

```
Application.persistentDataPath/charts/
  <chart-folder>/
    song.rbchart.json
    audio.ogg (or .wav)
```

On first launch, `ContentBootstrapper` copies the bundled demo chart from `Assets/StreamingAssets/charts/demo/` into that folder. To add your own charts, place a folder with a `*.rbchart.json` file and its referenced audio file in `persistentDataPath/charts/`.

The chart format is documented in `DESIGN.md` §3 and the step-by-step authoring guide is in [`docs/authoring.md`](./docs/authoring.md).

## Authoring a chart

You can create and preview charts without leaving the Unity editor:

1. Place an audio file in `Assets/Audio/` (or anywhere the editor can browse).
2. Choose **`Reflec Beat / Chart Preview`**.
3. In the **New Chart** section, name the chart, browse to the audio file, and click **Create Chart**.
4. Edit the generated `*.rbchart.json` under `Application.persistentDataPath/charts/<chartName>/`.
5. Select the chart in the **Chart Preview** window, set **Start Time** and **Duration**, and click **Preview Section**.
6. `GameplayScene` loads in Play mode with autoplay enabled so you can verify sync by ear and eye.
7. When the section feels right, stop Play mode and play the full chart from `ChartSelectScene`.

See [`docs/authoring.md`](./docs/authoring.md) for the full JSON reference, tick math, and troubleshooting.

## How it works

- **Music sync**: Audio is scheduled with `AudioSource.PlayScheduled(AudioSettings.dspTime + delay)`. All note timing is measured against the audio DSP clock via `SongClock`.
- **Spawning**: Notes are spawned `approachTime` seconds before their hit time.
- **Movement**: `NoteObject` updates its position each frame based on elapsed song time.
- **Input**: `TouchInput` captures touch/mouse and forwards `TouchData` (touch ID, normalized X, DSP time) to `GameController`.
- **Judging**: `Judge` evaluates taps/releases against the closest unjudged note using timing windows from `Constants`.
  - `JUST`: ±0.050s
  - `GREAT`: ±0.100s
  - `GOOD`: ±0.150s
  - `MISS`: beyond `GOOD` or unhit
- **Scoring**: `Score` tracks total, combo, and achievement rate; `ResultsUI` displays them.
- **Autoplay**: When enabled from the chart-select screen, `GameController` synthesizes perfect touches/releases for every note.
- **Duel mode**: Charts with `rival` notes activate a single-player duel. The CPU rival judges rival notes on the song clock, the player builds a Just Reflect gauge from hits, and a full gauge lets the player strike back. The result is shown on the results screen.

## Troubleshooting

### Chart list is empty

1. Make sure `ChartSelectScene` contains a `ContentBootstrapper` GameObject with the `ContentBootstrapper` script.
2. Check the Console for bootstrap errors. On Android, `StreamingAssets` must be read with `UnityWebRequest`, not `System.IO.File`.
3. The bootstrapper uses a version marker in `PlayerPrefs`. If you previously had a failed bootstrap, increment `CurrentVersion` in `ContentBootstrapper.cs` to force a retry.
4. Verify the demo files exist at `Assets/StreamingAssets/charts/demo/demo.rbchart.json` and `PlaceholderBeat.wav`.
